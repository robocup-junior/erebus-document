---

Erebus v27 ใช้กติกาปี 2027 ถ้าคุณย้ายมาจาก v26 การเปลี่ยนแปลงที่มีผลต่อหุ่นยนต์ของคุณมีดังนี้

| หัวข้อ | จนถึงปี 2026 | ตั้งแต่ปี 2027 |
|---|---|---|
| แบตเตอรี่ | - | ใหม่: หุ่นยนต์มี[แบตเตอรี่](/docs/rules/#the-battery)ที่ลดลงตามความเร็วของมอเตอร์ ถ้าหมด เกมจะจบลง |
| ช่องสัมผัส | - | ใหม่: [ช่องสัมผัส](/docs/rules/#contact-tiles)สีฟ้าอมเขียว การหยุดนิ่งบนช่องนี้ 5 วินาทีจะเปลี่ยนแบตเตอรี่ ในแผนที่เขียนเป็น `k` |
| หนองน้ำ | เวลาของเกมเดินเร็วขึ้น: x5 เมื่อเข้าครั้งแรก สูงสุด x10 | แบตเตอรี่ลดลงเร็วขึ้น เวลาของเกมไม่ได้รับผลกระทบ |
| ผู้ประสบภัย | สัญลักษณ์ Φ, Ψ, Ω | [หน้ายิ้ม](/docs/rules/#smiley-victims): หน้าเศร้า (บาดเจ็บ) หน้าเฉย ๆ (คงที่) และหน้ายิ้ม (ไม่บาดเจ็บ) ยังคงรายงานเป็น `H`, `S`, `U` |
| ผู้ประสบภัยปลอม | สัญลักษณ์สามมิติ | หน้ายิ้มสามมิติ |
| ข้อมูลเกม | คำตอบของ `G` ยาว 16 ไบต์ | คำตอบของ `G` ยาว 20 ไบต์ และลงท้ายด้วยระดับแบตเตอรี่ ดู[ข้อมูลเกม](/docs/programming/communication/#game-information) |
| ระยะการรายงาน | Erebus v26 รับรายงานที่ห่างจากสัญลักษณ์ได้ถึง 9 ซม. | ครึ่งช่อง (6 ซม.) ตามกติกา |
| พื้นที่ | สี่พื้นที่ พื้นที่ 4 ไม่บังคับ | สูงสุดสี่พื้นที่: มีพื้นที่ 1 เสมอ และผู้จัดอาจไม่ใส่พื้นที่ 2 ถึง 4 |
| Webots | R2023b | **R2025a** |
| Python | 3.9 ขึ้นไป | 3.10 ขึ้นไป |

[การรันครั้งแรกของคุณ](/docs/getting-started/)อธิบายวิธีใช้หน้าต่างควบคุมของ Erebus v27

## การอัปเดตโปรแกรมของคุณ {#updating-your-program}

1. อ่านคำตอบของ `G` เป็น 20 ไบต์ โปรแกรมที่รับเฉพาะ 16 ไบต์จะไม่ได้รับข้อมูลเกมอีกต่อไป
1. คอยดูระดับแบตเตอรี่ และวางแผนเส้นทางให้หุ่นยนต์ไปถึงช่องสัมผัสก่อนแบตเตอรี่หมด ดู[แบตเตอรี่](/docs/programming/battery/)
1. เพิ่มช่องสัมผัสลงในแผนที่เป็น `k`
1. ปรับการตรวจจับผู้ประสบภัยให้เข้ากับหน้ายิ้ม ตัวอักษรที่รายงานไม่เปลี่ยน
1. รายงานสัญลักษณ์จากระยะที่ใกล้ขึ้น ทั้งจุดศูนย์กลางของหุ่นยนต์และตำแหน่งที่ส่งต้องอยู่ห่างจากสัญลักษณ์ไม่เกินครึ่งช่อง
1. ตอนนี้หนองน้ำกินแบตเตอรี่แทนเวลา จึงควรคิดเรื่องนี้ในแผนการใช้แบตเตอรี่
1. ติดตั้ง Webots R2025a และ Python 3.10 ขึ้นไป แล้วตรวจสอบว่าโปรแกรมยังทำงานได้ ดู[การติดตั้ง](/docs/installation/)
