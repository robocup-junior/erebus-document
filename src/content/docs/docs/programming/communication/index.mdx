Your program talks to the game through two devices that every robot has:

- The **emitter** sends messages to the game. It does not need to be enabled.
- The **receiver** gets messages from the game. Enable it like a sensor.

Each section below is a complete program for the [starter robot](/docs/robot/). All the messages are listed in the [Message Reference](/docs/reference/messages/).

## Scoring wall tokens

To score a letter victim or a cognitive target, the robot must:

1. **Stop for more than 1 second** close to the token. Erebus ignores the report if the robot has moved in the last second.
2. **Send the position and type** of the token: X and Z in **centimeters**, and the type as one letter.

| Wall token | Type |
|---|---|
| Letter victim Φ (harmed) | `H` |
| Letter victim Ψ (stable) | `S` |
| Letter victim Ω (unharmed) | `U` |
| Cognitive target, sum 0 (Flammable Gas) | `F` |
| Cognitive target, sum 1 (Poison) | `P` |
| Cognitive target, sum 2 (Corrosive) | `C` |
| Cognitive target, sum 3 (Organic Peroxide) | `O` |

The types are letters, even though victims show symbols since 2026. The GPS gives meters, so multiply by 100.

<CodeTabs file="report" />

The robot must be on the same side of the wall as the token, and both the robot and the position you send must be close to it. The rules require at most half a tile, so aim for that. Erebus v26.1 checks a distance of 9 cm.

Run this program at the start of `world1.wbt`: there is no token there, so the history of the control window shows `Misidentification of Victim -5`. A wrong report, including a report of a fake, costs 5 points, and each token can only be scored once.

## Lack of progress

When the robot is stuck, a lack of progress moves it back to the last checkpoint and costs 5 points. It happens automatically after 20 seconds without moving, and your program can also call it by sending `L`. Each time, the game sends `L` to the robot, so that your program knows its position has changed.

<CodeTabs file="lop" />

The receiver can get different messages, so check the length of each one before reading it, as in the example.

## Game information

Send `G` to get the score and the time left. The game replies with a 16 byte message: the letter `G`, the score, the game time left and the real time left, in seconds.

<CodeTabs file="gameinfo" />

The game time runs faster in swamps, and the game ends when either time runs out. Use both to know when to head back to the start.

## Ending the game

Send `E` to end the game. If the robot is on the starting tile and has identified at least one wall token, it gets the 10% exit bonus.

<CodeTabs file="exit" />

:::caution
The game ends wherever the robot is when it sends `E`, and the robot cannot continue. Make sure it has returned to the starting tile first, and has [submitted its map](/docs/programming/map-bonus/).
:::
