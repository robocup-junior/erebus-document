In this tutorial you build a complete program, step by step. The robot drives around the maze avoiding walls and holes, and reports anything that looks like a wall token. It is the program you ran in [Your first run](/docs/getting-started/).

It uses the [starter robot](/docs/robot/), and what you learned in [Movement](/docs/programming/movement/) and [Sensors](/docs/programming/sensors/).

The complete program: <a href={mazePy} download="maze.py">maze.py</a> · <a href={mazeC} download="maze.cpp">maze.cpp</a>

### 4. Seeing a token
This function looks for wall tokens in a camera image. Tokens are bright squares on dark walls, so it looks for bright shapes that are roughly square and do not touch the edge of the image, where the floor usually is.

<CodeTabs file="maze" region="detect" />

This is a simple start: it cannot tell the symbols apart, and it does not see cognitive targets well. The [Wall Tokens](/docs/programming/wall-tokens/) tutorial shows how to do better.

### 5. Reporting
To score a token, the robot must stop for more than 1 second, and send its position and the type of the token. Each token can only be scored once, and reporting it again costs 5 points, so the program remembers where it has reported. [Communication](/docs/programming/communication/) explains these messages.

## How well does it do?
This robot wanders: it does not know where it has been, and it guesses the type of every victim. It gets stuck sometimes, and the game moves it back to a checkpoint after 20 seconds. That is fine for a first program.

## Try it
- Find the best speeds and distances for your robot.
- Follow the wall on one side: keep the side sensor at a constant distance, and turn when the front sensor sees a wall.
- Change the speed depending on how close the walls are.

Then, learn to score points in [Communication](/docs/programming/communication/).
